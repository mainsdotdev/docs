Mains uses your installed **Codex CLI** and its app server. [Install Codex](/install#install-codex), sign in with `codex login`, and open **Settings → Codex**.

Codex supports Code, Work, Chat, and Atlas. Mains reports an incompatible or outdated CLI in provider settings. The current integration accepts **0.153.0 or newer** and is developed against **0.160.0**; newer features can need a newer CLI than the minimum.

## Model and effort

Models and supported effort levels come from the runtime and your account. Choose them in the composer. Mains keeps each conversation's choices and remembers explicit preferences for new chats.

Effort choices vary by model. Fast mode uses Codex's fast service tier when available. Plan and Goal controls appear where the selected Mains mode supports them.

## Sandbox mode

| Mode | File access |
| --- | --- |
| Read Only | Read files without modifying them |
| Workspace Write | Write within permitted working directories |
| Full Access | Remove the normal filesystem sandbox restrictions |

Selecting **Full Access** opens a confirmation describing access to files, terminal commands, the internet, and connected apps.

Approval policy remains a separate setting. Full Access does not mean every connected service will authorize every action.

## Approval policy

| Policy | Behavior |
| --- | --- |
| `on-request` | Ask when Codex requests permission |
| `untrusted` | Ask for operations outside trusted commands |
| `never` | Do not ask for escalation; operations that need it cannot proceed through an approval prompt |

Read requests in [Approvals](/approvals). Organizational policy can restrict these choices.

## Network and web search

**Network Access** controls outbound access for workspace-write execution. **Web Search** controls the provider's web-search capability. They are different controls.

**Skip Git Check** lets a run use a non-Git directory when applicable. Work already uses a managed execution directory and its own mode policy.

Work applies workspace-write and hides developer permission controls. Chat enforces read-only access. Existing runs retain their [mode](/modes).

## Conversation memory

Under **Conversation memory**, you can:

- Turn **Use saved memories** on or off.
- Choose whether to **Include chats that use tools**, including MCP or web search.
- **Clear saved memories** on this device after confirming.

These controls manage Codex memory, not Mains's chat history or Atlas Pages. A runtime or managed policy that does not support a control is reported in Settings.

## Other capabilities

Codex supports [continue and fork](/runs), [native review](/reviews), [subagents](/codex/subagents), [queue and steering](/codex/steering), [voice](/voice), plugins, and [MCP apps](/mcp-apps).

Account usage and available limits appear in Settings when reported by Codex. They remain separate from Mains's local [usage estimates](/stats).
