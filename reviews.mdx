An agent review inspects your Code workspace and reports findings. It is separate from commenting on a GitHub PR.

## Request a review

Describe what to review and which risks matter:

```text
Review the uncommitted changes.
Look for incorrect behavior, missing validation, and regressions.
Give each finding a file location and a concrete fix.
```

You can invoke a code-review skill when one is installed. A `/code-review` command is not guaranteed to exist in every provider's default installation.

Claude, Copilot, and Cursor can record workspace reviews through Mains's **SaveReview**, **SaveFinding**, and **SaveFindings** tools in Code mode.

## Codex review

Codex has native review targets for **uncommitted changes**, a **base branch**, a **commit**, and **custom instructions**. Its findings are mapped into workspace review data.

Choose the target that matches your question. Custom instructions describe what to inspect; they are not a promise that every arbitrary Git range has its own selector.

## Read findings

A structured finding can include severity, file and line range, message, rationale, and a suggested fix.

Workspace reviews use **Open**, **In Review**, **Approved**, and **Rejected** statuses. Codex priorities map to the app's severity categories.

A review status is local metadata. It does not approve or reject a GitHub PR.

## Act on feedback

Open the referenced code, ask a follow-up, or attach your own [line comments](/diff-viewer). Review the updated diff and verify the relevant behavior before committing.

For comments that should appear on GitHub, use [Pull request review](/pull-requests).
