Mains drives **Cursor Agent CLI** through the Agent Client Protocol. Install the CLI and sign in before starting a Cursor run.

```bash
curl https://cursor.com/install -fsS | bash
agent login
```

Open **Settings → Cursor** for account and CLI status. Follow the update guidance there if your CLI is too old for supported model controls.

## Operating mode

| Cursor mode | Intent |
| --- | --- |
| Agent | Execute tools to complete the task |
| Plan | Plan before executing |
| Ask | Answer questions and explore without making changes |

These are Cursor's operating modes inside Mains's **Code** experience. They are separate from Mains's Code, Work, and Chat modes. Cursor currently offers only Code in Mains.

## Model and effort

Mains discovers the runtime's available models and supported configuration options. Select them in the composer. If an option is unavailable, update the CLI or choose a model that supports it.

Conversation settings are retained on continuation. Cursor also supports forking an existing conversation.

## Permissions and tools

When Cursor asks for permission, Mains displays an [approval request](/approvals). Available options come from the request and runtime.

In Code, Mains provides review-recording and [package-check](/dependency-guards) tools. Git commits and PR creation use [Git actions](/git-actions), or the shell when explicitly requested.

Cursor-native tasks, todos, and image generation can appear as ACP activity. They are separate from Mains's plugin marketplace, which is not available for Cursor.

For CLI-specific setup, see the [Cursor CLI documentation](https://cursor.com/docs/cli/overview).
