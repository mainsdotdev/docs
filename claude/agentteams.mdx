Claude can delegate focused work to subagents. Mains shows their progress, tool activity, and results in the subagent panel.

## Ask for delegated work

Use a clear division of responsibility:

```text
Review these changes with three subagents:
one for correctness, one for security, and one for missing tests.
Combine the findings and do not modify files.
```

Each subagent has its own context. Separate contexts do not create separate working directories; coordinate edits or use [worktrees](/workspaces) for isolated implementation tasks.

## Follow the results

Open the subagent panel to inspect what a worker is doing and what it returned. The parent conversation remains the place to give instructions and review the combined result.

Available agent definitions and tools depend on the bundled Claude runtime, repository configuration, and run mode.

## Interactive agent teams

Claude Code's experimental **agent teams** are a separate upstream feature with teammate messaging and shared task coordination.

The upstream switch is:

```json
{
  "env": {
    "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1"
  }
}
```

It belongs in Claude's user or project settings. Enabling it does not add terminal teammate controls to Mains.

Mains runs Claude through the **Agent SDK**. Current upstream guidance limits teammate spawning to interactive sessions; SDK sessions use ordinary subagents. Do not treat a subagent panel as proof that an interactive team has formed. See the [official agent teams guide](https://code.claude.com/docs/en/agent-teams).

Use ordinary subagents for delegated work inside Mains. Provider behavior can change with runtime updates.

## Cost and access

Delegated work consumes additional tokens. Subagents still operate under the run's tools and permissions; they do not give a Chat run file-writing access.
