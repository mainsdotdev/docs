Type `/` in a Claude composer to see commands available to that runtime and working directory. The list includes provider commands and commands supplied by your configuration or plugins.

The available list changes with the bundled Claude version. Use that list rather than assuming every terminal command has an in-app equivalent.

## Custom command locations

| Scope | Directory |
| --- | --- |
| User | `~/.claude/commands/` |
| Project | `.claude/commands/` |

Create a Markdown file such as `.claude/commands/review-changes.md`:

```markdown
---
description: Review recent changes for regressions
allowed-tools: Read, Grep, Glob
---

Review the recent changes.
Check behavior, input validation, and missing tests.
Report findings with file locations. Do not modify files.
```

Select `/review-changes` from the command menu when it appears.

## Arguments

Use `$ARGUMENTS` for the supplied text or positional arguments such as `$1`.

```markdown
---
description: Investigate an issue
argument-hint: [issue-number]
---

Investigate issue #$1 and explain the likely cause.
```

## Commands and skills

Commands provide reusable prompts. [Skills](/skills) package broader instructions and supporting resources and can be selected when their task matches your request.

A custom `/create-pr` or `/code-review` command exists only when your configuration supplies it. Use [Git actions](/git-actions) to create a PR directly.

Provider-native syntax follows the [Claude skills and commands documentation](https://code.claude.com/docs/en/skills).
