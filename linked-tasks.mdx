Attach an issue or task to your next message so the agent has its requirements alongside the relevant code.

## Available sources

| Service | Context |
| --- | --- |
| GitHub | Issues |
| GitLab | Issues |
| Linear | Issues |
| Jira | Tickets |
| Asana | Tasks |
| Trello | Cards |
| Sentry | Error signals, including diagnostic details |

GitHub pull requests have a separate live [PR view](/pull-requests). They are not imported as ordinary issue records.

## Add task context

<Steps>
  <Step title="Connect and sync">
    Open **Settings → Connections**, authenticate, and select the repositories, teams, projects, or boards you want to sync.
  </Step>
  <Step title="Scope the project">
    Link those resources to your Code project to find the relevant issues together.
  </Step>
  <Step title="Attach the item">
    Pick an issue from [Tasks](/tasks) or the composer `@` menu. Review its context chip before sending.
  </Step>
  <Step title="Add implementation context">
    Attach related files or code selections and describe the result you want.
  </Step>
</Steps>

## Freshness

Issue context comes from Mains's local synced data. Use **Sync** or [Auto Sync](/automations) to refresh it before starting work that depends on recent changes.

Attaching an issue does not guarantee that every source comment or later edit is included. Inspect the imported detail when that matters.

## Status and publishing

Workspace status is local to Mains. It does not automatically move the linked issue through your tracker's workflow.

When you draft a PR, review the description and include the issue reference you want. Linking an issue does not submit tracker comments, create a PR, or close the issue by itself.
