Context is the material you attach to your next message. It helps the agent understand the task and find the relevant information.

## Ways to attach context

| Context | How to add it |
| --- | --- |
| Files and images | Use the attachment picker, paste an image, or drop files anywhere in the chat |
| Workspace files | Select a file through `@` or the [file explorer](/file-explorer) |
| Code selection | Select code in the editor and choose **Add selection to chat** |
| Issues and signals | Select synced items through `@` or [Tasks](/tasks) |
| Browser annotations | Select elements and add a comment in the [browser](/browser) |
| Review comments | Comment on a line or range in [Review](/diff-viewer) |
| Mac window | Capture it with [Lens](/lens) |
| Skill or plugin | Select an available entry from the composer menu |
| Shared material | Add sources to a [collection](/collections) |

Review the chips before sending. You can remove an attachment, edit an annotation comment, or open a referenced file or skill.

## What gets sent

The next message includes the selected context and uploaded originals. Images and files you upload are saved with the run so they remain available in its history and forks.

A Lens capture includes the window image and, when Accessibility permission is available, readable text from the window. A browser annotation includes the captured page, selected elements, and your comment.

MCP apps can also provide selections to the composer. Review that context before sending it with your message.

## Shared sources

Collection sources apply to subsequent turns in that collection's conversations. They are stored copies, so changes to an original file do not update a source automatically.

Your agent also loads repository instructions and skills according to its provider configuration.

## Privacy and permissions

Attached prompts, files, and tool results used by the agent can reach the selected AI provider or connected service. See [Privacy](/privacy).

Attaching a file does not grant unrestricted filesystem access. The run's mode, sandbox, additional-directory settings, and tool approvals still determine what the agent may do.
