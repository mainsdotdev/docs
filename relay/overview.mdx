**Mains Connect** lets you use the local backend, share this machine with another device, or connect to a backend on another machine.

Older releases and links call this feature **Relay**. The existing Relay documentation URLs continue to describe Mains Connect.

## Choose where work runs

| Setup | Use it for |
| --- | --- |
| [Share this machine](/relay/share-this-machine) | Let a phone, browser, or another desktop reach the running Mac app |
| [Standalone server](/server) | Keep a backend available without Electron on macOS or Linux |
| [SSH tunnel](/relay/ssh-tunnel) | Reach a remote backend without exposing its port to the network |
| [Direct URL](/relay/direct-connection) | Connect over a trusted LAN or secure Tailscale/TLS endpoint |
| [iPhone companion](/mobile) | Follow runs, send prompts, and answer requests from your phone |

Repositories, provider credentials, and execution stay on the chosen backend. The client displays its work and sends requests.

## Open Connect

Use **Mains Connect** in the desktop navigation rail. **This machine** controls hosting. **Run on** lists your local and saved remote backends.

Choose a saved backend and connect. Return to **Local (this machine)** when you want your Mac's work again.

The browser client is already connected to the server that served it. It does not offer the desktop's backend-switching controls.

## It is a connection, not a sync

Remote clients use one backend's database. Mains Connect does not merge workspaces or histories from independent machines.

[Bridge](https://mains.dev/bridge) is a separate, coming-soon sync feature.

## Access and compatibility

Use device pairing for a phone and one-use login links for browsers. A desktop direct or SSH connection can use the backend's owner token.

Keep client and backend versions compatible. Native desktop features such as Lens and the embedded browser do not become remote capabilities merely because the backend is connected.
