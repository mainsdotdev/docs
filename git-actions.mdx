Open the session panel in **Code** to work with Git. The panel reads the current working tree and branch, so changes made outside Mains appear here too.

## Changes and branches

Expand **Changes** to see modified and untracked files. Click a file to open its diff. Refresh when you need to reread Git state.

Use the branch row to switch, create, or rename a branch. Creating a branch from the current branch keeps your uncommitted work and makes that parent branch the workspace's PR base.

Git can reject a switch when files conflict or the branch is already checked out in another worktree. Mains shows the error so you can resolve it.

### Discard

You can discard one file or all working-tree changes after confirming.

<Warning>
  Discard restores tracked files from Git and deletes untracked files. It can remove your edits and other agents' work. Use a [turn's Undo](/turn-changes) when you want to reverse only that turn.
</Warning>

## Pull

The panel shows commits behind the upstream branch and offers **Pull** when it can fast-forward. If the branches have diverged or another Git condition blocks the operation, it stops and explains why.

## Commit or push

| Control | Behavior |
| --- | --- |
| Commit message | Write your own or generate one from the changes |
| Include unstaged | Stages the working-tree changes before committing when enabled |
| Commit | Creates a local commit |
| Commit and push | Creates a commit and pushes the current branch |
| Push | Pushes existing commits without making a new commit |

Generation uses the selected provider and model, plus your commit instructions. Review the draft before submitting.

Mains rejects commits from detached `HEAD` and does not create an empty commit when nothing is staged.

## Create a pull request

PR creation requires a **GitHub remote** and [GitHub CLI](https://cli.github.com) authentication.

Choose the **base branch**, title, description, and whether to create a **draft**. The workspace's base is the starting choice, with the project default as fallback.

Generated PR text considers the branch's commits and current changes, including new files. The description editor supports Markdown formatting and preview.

Mains verifies the recorded origin, pushes the head branch, and creates the PR with an explicit head and base. A changed origin or a PR targeting its own head is rejected before creation.

### Images and videos

Paste, drop, or attach images up to **10 MB** and videos up to **100 MB**. They upload when you create the PR.

Media upload requires **GitHub CLI 2.99 or newer**. If the PR is created but an attachment step fails, review the reported warning and check the resulting description.

## Publish a repository

If there is no `origin`, the panel offers **Publish repository**. Choose the owner, repository name, visibility, and protocol. Publication creates a GitHub repository and adds its remote.

The default visibility is private. Review the choice before publishing.

## Writing conventions

Set defaults in **Settings → Git** or overrides in the [project settings](/projects). Project instructions take precedence for generated commit and PR text.

Agents do not receive `CommitChanges` or `CreatePR` tools. Use this panel, or explicitly ask the agent to use Git through its shell when that is appropriate.
