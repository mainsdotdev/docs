A Code workflow starts in a [workspace](/workspaces) and ends with changes you have reviewed. Work and Chat use a different structure; start with [modes](/modes) if you are working on documents or research.

## Choose the task and checkout

Add a repository with **Add Project**. Mains groups checkouts of the same repository under a [project](/projects).

Use your existing checkout for a single task. For concurrent tasks that will edit the same repository, enable worktrees or create a separate worktree. Separate chat tabs alone do not isolate files.

If you use an issue tracker, connect it in **Settings → Connections**, select resources to sync, and open [Tasks](/tasks). Attach the issue to your next prompt.

## Provide context

Use `@` to select relevant files or issues. Add a code selection, a [browser annotation](/browser), or a [Lens capture](/lens) when it explains the problem better than text.

Describe the expected behavior and how to verify it:

```text
Fix the login error described in the attached issue.
Keep the existing authentication flow and run the relevant tests.
```

## Follow the run

The [transcript](/runs) shows messages, tool activity, plans, and requests for input. [Approvals](/approvals) let you allow or deny an operation before it continues.

You can switch workspaces while the agent runs. With Codex, [steer the active turn](/codex/steering) or queue a follow-up.

## Review and refine

Open [Changes](/diff-viewer) for the current uncommitted diff. Comment on a line or range and send your feedback to the chat.

Use a [turn change card](/turn-changes) when you want the patch from one turn. Request an [agent review](/reviews) when you need another inspection pass.

## Commit, push, and create a PR

Use the [Git actions panel](/git-actions) to review the branch, pull incoming changes, commit, push, and draft a pull request.

Choose the PR base and review its title, description, and attachments before creating it. Project-level instructions can guide generated commit messages and PR descriptions.

A [GitHub PR review](/pull-requests) is separate from your local workspace review. Comments submitted from that view go to GitHub.

## Archive finished work

Archive a workspace to hide it while retaining its history. Archiving can run your project's archive script; it does not automatically remove the worktree. Restore it from **Settings → Archive**.
