An Atlas Page is an editable document kept in your library independently of a conversation. You can write it yourself or work on it with Claude or Codex.

## Create and edit

Open [Atlas](/atlas) and choose **Start a page** or a template. The starter creates a blank Page and prepares a draft prompt; the agent begins only when you send it.

Type `/` in the editor to insert headings, lists, tables, images, and other blocks.

Mains keeps a draft on this device as you type and saves it to the backend about every 30 seconds while you keep editing. It saves again when you close the window. If a save fails, the draft stays on this device.

Use the Page's chat to ask for a section, rewrite, or summary:

```text
Add a rollout checklist to this page.
Include owners, verification steps, and a rollback decision.
```

You can edit alongside the agent. If a save conflicts with a newer version, Mains retains your draft instead of silently overwriting the newer content.

## Page conversations

Choose a previous Page chat or **New page chat** from the chat target menu. Page conversations use Work mode and the selected Claude or Codex space.

A Page-backed chat in the regular sidebar has an **Open page** button. Links to a Page in agent replies also open it in Atlas.

Work conversations can create and update Pages with Atlas tools. Code and Chat conversations can read Pages; Chat remains read-only.

## History

Open **History** from the Page menu to inspect saved versions and whether you, the agent, or a restore made them.

History lists the last version of each of your 10 most recent editing sessions. A session ends after 10 minutes without changes, after 30 minutes, or when a different author, such as the agent, makes a change. Autosaves within a session count as one version, so history does not list every save.

Restoring a version creates a new current version marked **Restored**. The version it replaces stays in history, so you can go back.

Mains always preserves the current revision and unresolved conflict revisions, even beyond the 10-session history window.

On a Page that Bridge has never synced, Mains removes revisions outside the retained checkpoints. For synced Pages, it keeps autosaves within retained sessions and removes older history while preserving the current revision and unresolved conflicts.

Page history tracks Page content and title. Your current icon and cover are kept separately.

## Icons, covers, and tabs

Choose **Add icon** to pick an icon. Choose **Add cover** to open **Page cover**. There you can upload an image with **Upload image**, pick one under **Your images** (use **Show more** for the rest), or choose from the bundled gallery.

The gallery has 40 covers in five sections: **Color & Gradient**, **British Library**, **Birmingham Museums Trust**, **The Metropolitan Museum of Art**, and **NASA**. A gallery cover is stored once in your Atlas. It does not appear in your library or under **Your images**.

After you pick a cover, choose **Change cover** to swap it or **Reposition** to adjust its framing. Framing is stored on the device where you set it.

In Work mode, the agent can set a Page's icon to a single emoji and choose a cover from the gallery. Changing only the icon or cover does not add a history version.

Open several Pages in tabs. Closing a tab closes the view and preserves the Page. Use Trash when you want to remove it from the library.

## Import and export

The Page menu supports **Markdown** and **JSON** import and export. Use Markdown for portable text. JSON preserves the native block structure.

You can also copy the Page content and move it into a project.

## Trash

Open **Trash** to view removed Pages. Opening a trashed Page keeps it read-only; restore it before editing.

Permanent deletion needs confirmation. Pages can retain embedded files through their revision history, so a file still used by a restorable Page cannot be permanently deleted.
